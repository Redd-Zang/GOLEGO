# 扫码上传与自动领取

在已验证 Codex CLI 生图的环境启动单个服务实例。替换路径，并保持终端运行。

```sh
python "SKILL_PATH/scripts/qr_station.py" --data-dir "ACTIVITY_PATH/af19-data" --bind 127.0.0.1 --port 8919 --workers 5 --limit 50
```

打开 `http://127.0.0.1:8919/`，选择照片后直接点击生成。无需选择人数。默认 JPEG、PNG、HEIC，最大 12 MB。浏览器领取 Cookie 有效期 90 天，同一 Cookie 一次提交；换浏览器或清除 Cookie 可以再提交。照片进入独立文件夹，最多五个生成任务同时运行，其余排队。

## 保存位置与恢复

`ACTIVITY_PATH/af19-data/<会话哈希>/upload.*` 为来图，同目录 `poster.png` 为成品。`jobs/<任务哈希>/` 保存参考图、场景底图及任务状态。Cookie 是领取凭证，避免分享来宾会话信息。

来宾用同一浏览器、同一域名再扫码可以继续查看状态和领取。电脑与服务需持续运行。站点每次启动把上轮未完成的提交标为失败，避免无限等待；已完成海报继续可领。人工确认失败原因后，可用原会话哈希作为 message 调用 `guest_job.py qr <会话哈希> <upload路径> --jobs <af19-data/jobs>`，成功后把对应 `poster.png` 复制至该会话文件夹，并移除 `failed` 标记。不要在旧任务仍运行时重复启动服务或修复任务。

## 额度与提醒

累计 50 次提交后拒绝新上传，继续处理已接收队列。终端打印是否加额的询问，并写入数据目录的 `limit-reached.txt`。Agent 检查该文件后在聊天里询问用户新的累计上限。普通终端不会主动发起 Codex 聊天。收到明确新上限后，等待当前队列完成再重启服务并修改 `--limit`，沿用同一数据目录。

## 公网与二维码

目标电脑的本地地址只在该电脑可用。用户授权公网开放后，可沿用当前已安装的 cloudflared 工具建立指向 `http://127.0.0.1:8919` 的临时隧道。先读取工具 `--help` 核对支持的参数，再运行 `cloudflared tunnel --url http://127.0.0.1:8919`。生成二维码前用公网实际请求首页、上传测试、状态及领取接口。

```sh
python "SKILL_PATH/scripts/entry_qr.py" "PUBLIC_HTTPS_ORIGIN" "ACTIVITY_PATH/entry-qr.png"
```

二维码只包含活动入口域名。临时隧道重建可能换域名，需重制二维码，旧域名的 Cookie 也不会自动迁移。新电脑不会继承旧服务的临时域名。仅复制本技能不代表公网入口已部署。

该服务是活动内测实现。参数 --workers 表示并发上限，实际速度和可用性取决于账号及内置生图服务；技能不包含独立生图额度。上传到 failed 的提交也计入累计额度。
